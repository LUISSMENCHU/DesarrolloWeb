Evolucionar la aplicación web desarrollada en la Tarea 3 conectando la interfaz de usuario en React con una arquitectura de backend real construida con Node.js, Express y MongoDB.

El estudiante reemplazará los datos y la autenticación simulada de la entrega anterior por peticiones asíncronas hacia su propia API RESTful. La aplicación deberá persistir la información de usuarios y entidades de negocio en una base de datos en la nube (MongoDB Atlas), sincronizando las respuestas del servidor con el estado global de la aplicación (vía useContext + useReducer o Redux Toolkit, según la opción elegida en la Tarea 3).

Instrucciones Generales
Crear una nueva rama en el repositorio de GitHub llamada Tarea4.

Configurar un clúster gratuito en MongoDB Atlas.

Gestionar credenciales y puertos de forma segura mediante variables de entorno (.env). No subir contraseñas ni cadenas de conexión directas al repositorio público.

Requerimientos Técnicos
Construir un servidor backend modular aplicando una separación limpia de responsabilidades (rutas, controladores, modelos y configuración de conexión):

Conexión a Base de Datos: Establecer conexión persistente y control de errores hacia el clúster de MongoDB Atlas usando Mongoose.

Modelos de Datos:

User: Debe contener al menos nombre completo, correo electrónico, contraseña/credencial, rol (ej. admin/cliente) y marcas de tiempo (timestamps).

Recurso / Entidad del Negocio: Modelo para gestionar la información temática del proyecto (ej. productos, servicios, citas, reservas, catálogo o pedidos).

Endpoints Requeridos:

Autenticación:

POST /api/auth/register: Registro de nuevos usuarios en MongoDB.

POST /api/auth/login: Validación de credenciales contra la base de datos y retorno del objeto de usuario verificado.

CRUD de la Entidad de Negocio:

GET /api/recursos: Listado general con soporte de filtrado básico o búsqueda mediante query parameters.

GET /api/recursos/:id: Consulta detallada por path parameter.

POST /api/recursos: Creación de un nuevo elemento a través del request body.

PUT /api/recursos/:id o PATCH /api/recursos/:id: Actualización de la entidad.

DELETE /api/recursos/:id: Eliminación del recurso en la base de datos.

Conectar el cliente React a la API desarrollada utilizando fetch o axios:

Autenticación Real:

El formulario de la Tarea 3 debe enviar las credenciales al endpoint POST /api/auth/login.

La respuesta exitosa del servidor disparará la acción global (LOGIN) para persistir la información del usuario en el estado transversal.

Manejar adecuadamente respuestas de error (ej. credenciales inválidas 401) mediante mensajes contextuales en la interfaz (como Alert de React-Bootstrap).

Consumo de Entidades:

Reemplazar arreglos estáticos locales por peticiones GET a la API.

Implementar estados de carga (loading) y visualización de errores al interactuar con el servidor.

Operaciones de Escritura desde la UI:

Permitir al usuario crear, actualizar o eliminar registros en la base de datos desde la interfaz (ej. formulario de alta o botón para eliminar/modificar un recurso).

La vista de perfil o dashboard debe recuperar los datos directamente del usuario autenticado en la base de datos.

Mostrar información adicional almacenada en MongoDB utilizando componentes de React-Bootstrap (Card, Badge, ListGroup, Table).

Entrega:
Subir el código actualizado del sitio web al mismo repositorio de GitHub, en una nueva rama Tarea4.
Enlaces directos a las aplicaciones desplegadas (Frontend en Netlify/Vercel y Backend en Render/Railway).

Colección de pruebas de endpoints (archivo .json para Postman/Thunder Client o listado detallado de endpoints con payloads de ejemplo).

Diagrama o resumen de la arquitectura de carpetas del backend.

Nombre completo y número de carné de cada integrante, detallando las secciones, endpoints y componentes desarrollados por cada uno.
